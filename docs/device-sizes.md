# Device sizes: the source of truth

**Rule (Jonah, 2026-10-23):** this file is the law for every device size used in Cratebox Suite iOS: layout work,
releases, and the personal HEAT build (`personal/heat`). Don't estimate sizes or take them from memory. If a device
isn't here, measure it first (Actions → iOS checks → Run workflow, `measure: true`, `devices: none`), then add it.

## Sources

1. **Measured:** the app itself, run in Xcode's simulators on GitHub's macOS runner (ios.yml run
   [39886977167](https://github.com/zonahbear/cratebox-iOS-suite/actions/runs/39886977167), iOS 26.2 runtime,
   2026-10-23). It records `-metrics`: the window scene's screen bounds, scale and native pixels, and the key window's
   landscape safe-area insets. Raw output: branch `ci-logs-preview`, `shots/metrics.txt`.
2. **Reference:** [ios-resolution.com](https://www.ios-resolution.com/), fetched by the same CI run on 2026-10-23
   (`shots/ios-resolution.html` on `ci-logs-preview`). It's a third-party site, so where it and a measurement
   disagree, the measurement wins. Safe areas come only from measurements.

## What this means for the layout

- **Display Zoom** changes the points the app gets. The reference's "Display Zoom" column is the zoomed size in
  portrait points. The iPhone SE (3rd gen) zooms to 320 × 568, so the app gets 568 × 320 in landscape, which matches the
  tester's screenshot (1136 × 640 px at 2×). CI checks this size with `-screen 568x320`.
- The SE has no landscape safe-area insets (0 / 0 / 0), so it uses Touch mode (CompactPhone.swift, no edge strips). Every measured
  Face ID or Dynamic Island phone gets 47–68 pt side insets and a 20 pt bottom inset, and uses the standard layout
  unless the setting is on.
- The rules in `PhoneScreen.autoCompact` (side insets under 30 pt, middle under 640 pt, or height under 360 pt) are
  checked against the measured sizes above. Before you change them, re-check this table, including the Display Zoom
  sizes below.
